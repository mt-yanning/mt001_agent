1.1 验证通过的能力通路(直接影响设计)
--------------------------------------------------------------------------------

  能力      通路(代码核实)                       mock      Gazebo
  ──────────────────────────────────────────────────────────────────
  底盘      /cmd_vel 或 bridge base_velocity      ✅        ✅
  夹爪      /arachne/gripper/command              ✅        ✅
  机械臂    两环境不同(见 1.2 修正1)              JointTraj  gui_joint_states
  状态反馈  bridge get_robot_state(每项带age_sec) ✅        ⚠需重映射odom
  IK/FK     AuboI5Kinematics.solve_pose() 现成    ✅纯数学   ✅纯数学

--------------------------------------------------------------------------------
1.2 ⚠ 修正1——机械臂通路 mock ≠ Gazebo，且都不走 bridge
--------------------------------------------------------------------------------
  · mock：发 JointTrajectory 到 /aubo_arm_controller/joint_trajectory
          (给目标关节角 + 时长，mock 自带 smoothstep 平滑插值，最省事)
  · Gazebo：发 JointState 到 /arachne/gui_joint_states
          (给绝对关节角流，需自己插值；由 gazebo_demo_control_bridge C++节点转发)
  · bridge 的 arm_cartesian_jog / arm_joint_jog 在两个仿真环境都【静默失败】
    (读代码确认：它们发到 /arachne/aubo/joint_velocity_command，
     mock 和 Gazebo 都不订阅这个话题)
  → 结论：技能库的机械臂技能要按环境抽象这两条通路。底盘与夹爪两环境统一。

--------------------------------------------------------------------------------
1.3 ⚠ 修正2——IK 白送，别自己写
--------------------------------------------------------------------------------
  arachne_operator 的 AuboI5Kinematics 类(agent_bridge 已 import)自带：
    · fk(q) ..................... 正运动学
    · solve_position(...) ....... 3自由度位置 IK
    · solve_pose(...) ........... 6自由度全位姿 IK(阻尼最小二乘)
  纯 numpy、无 ROS 依赖，mock/Gazebo 都能直接调。
  → 技能库的 reach_to(xyz) 直接用 solve_pose，不用抄 autopick 的手写 IK。

--------------------------------------------------------------------------------
1.4 感知现状(决定视觉分阶段)
--------------------------------------------------------------------------------
  · 末端相机 xacro 现成(ee_camera.xacro，Orbbec Gemini335)，但 Gazebo 演示里
    with_ee_camera:=false 关掉了，且 ros_gz_bridge 没桥接任何图像话题
  · 当前 Gazebo 环境无相机、无 /joint_states(ROS侧)、无 TF、无雷达
    ——它是为 autopick 一个演示定制的最小环境，不是通用仿真平台
  → 视觉感知必须分阶段：先上帝视角桩，后开相机 + 接 VLM(见完全版)

第二部分  不变骨架：三层架构(所有版本共用)
================================================================================

  ┌──────────────────────────────────────────────────────────────┐
  │ ③ 大脑 Brain (LLM)                                            │
  │    只调技能，输出结构化决策(JSON)                             │
  └───────────────────────────┬──────────────────────────────────┘
                              ↓ 调 navigate_to("work_table")
  ┌──────────────────────────────────────────────────────────────┐
  │ ★② 技能库 Skill Library ← 你造的核心，项目主要工程量          │
  │    用原语组合出中层参数化技能                                 │
  └───────────────────────────┬──────────────────────────────────┘
                              ↓ 发 JSON / JointTrajectory / JointState
  ┌──────────────────────────────────────────────────────────────┐
  │ ① 原语 Primitive ← Arachne 现成，你不用写                     │
  │    bridge 10工具 + 机械臂通路 + AuboI5Kinematics              │
  └───────────────────────────┬──────────────────────────────────┘
                              ↕ /arachne/agent/command + /status 闭环

  关键理念：LLM 不直接调 base_velocity，而是调 navigate_to("桌子")；
            技能库把后者翻译成一串 base_velocity + odom 闭环。
            ——那 10 个 bridge 工具是"执行器(actuator)"，不是 BUMBLE 意义上的
              "技能"。中层技能库是缺的、需要你造的，也是论文的核心贡献。

  三个版本 = 在这骨架上按文献逐步加模块。

第八部分  代码审查得出的关键坑与事实速查(动手前必看)
================================================================================

  1、ok:true ≠ 机器人动了
     agent_bridge 对多个工具静默转发/发布，不检查有无执行。
     base_relative/base_turn：只转发JSON到grasp_task，无订阅者=静默失败。
     arm jog：mock/Gazebo 都不订阅其输出话题=静默失败。
     → Agent 必须读 /arachne/agent/status 的 latest.odom / arm_joints
       实测确认状态变化。这个"发→观察→确认"闭环本身就是你的核心价值。

  2、里程计话题不一致
     mock=/odom，Gazebo=/gz/odom。agent_bridge launch 没暴露 odom_topic，
     Gazebo 下要用 ros2 run + -p odom_topic:=/gz/odom(它是声明过的参数)。

  3、机械臂三环境通路(见第一部分修正1)
     mock=JointTrajectory / Gazebo=gui_joint_states / 真机=joint_velocity。
     仿真下别用 bridge 的 arm jog 工具。

  4、base_relative/base_turn 需另启 grasp_task_server
     否则静默失败。启动时确认 execute_real=False(仿真安全)。

  5、别调 aubo_teach 工具(安全风险，会让机械臂泄力)，从给LLM的工具清单删掉。

  6、限速静默夹紧
     发 linear_x=100 会被静默夹到 0.20，发 duration=9999 夹到 2.0。
     Agent 要从返回的 data 字段读实际生效值，别假设发什么就是什么。

  7、死人开关(deadman)
     底盘/机械臂速度指令由80Hz定时器持续发布，到 duration_sec 到期
     (最长2秒)自动归零。即使 Agent 崩溃机器人也会停。

  8、上 Gazebo 前必须核实(可能是第一个大坑)
     ros2 pkg list | grep arachne   ← 看 arachne_gazebo 是否编译成功
       (它依赖 Gazebo Garden 的 gz-msgs10，最可能没编上，而 Gazebo 控制的
        关键桥接节点 gazebo_demo_control_bridge 就在这个包里)
     gz sim --version               ← 核实 Gazebo 版本

  9、环境准备可用官方脚本(比手记三条更彻底)
     source /root/autodl-tmp/Arachne/scripts/env/arachne_env.sh
     (它自动剔除 conda/venv 路径、unset PYTHONHOME、设 FastDDS=UDPv4)

  10、别改 Arachne 仓库(没推送权限，之前误删过)；所有产出放 mt001_agent/。
